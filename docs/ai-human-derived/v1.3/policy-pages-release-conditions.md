## 3. 公開を妨げる条件と解消方法
1. 制定日の確定 → 代表者が承認した日を入れ、「(予定)」表示を削除
2. 所在地の表示方法の決定 → 法務確認後に文言を差し替え
3. contact@ の送受信確認 → 代表者が外部アドレスから送信・返信して結果を記録
4. 重大リスク(MFA未設定、RDP等)の確認・是正 → 上表の確認方法で実施
5. 本番での表示確認 → 公開後に代表者がスマホで確認

## 4. ロールバック手順
- 公開後に問題が出た場合: `git revert -m 1 <PR #15のマージコミット>` を新しいPRで `main` に反映(履歴は書き換えない)。Firebaseの旧リリースへの戻しは、代表者の承認のうえコンソールから実施。
- 影響範囲: 追加2ページ、36ページのフッター/問い合わせ欄の追記、トップの追記、sitemap2行。revert で `/privacy`・`/security` は404に戻り、リンクも消える。
